Find a flipped bit using three checks

Four data bits occupy positions 3, 5, 6, 7. Positions 1, 2, 4 hold even-parity bits. XOR returns 1 when a group has an odd number of ones; choose the parity bit to make that count even.

Positions increase from left to right, exactly as in your C++ file. P = parity; D = data. At step 5, click a bit to introduce one error.

This decoder assumes zero or one flipped bit. Ordinary Hamming(7,4) cannot distinguish a double error from a single error to correct; it can miscorrect two flipped bits.

Predict: S1 = 1, S2 = 0, S4 = 1. Which position do you flip?

Write it from memory · Hamming
  1. Validate four binary digits. Allocate eight list elements.
  2. Place data at 3, 5, 6, 7. Calculate parity at 1, 2, 4.
  3. Read seven received bits. Recheck all three parity groups.
  4. Compute error = 4*s4 + 2*s2 + s1; flip if nonzero.
  5. Extract 3, 5, 6, 7. Try data 0000, then 1111; flip a parity bit too.

Trace to reproduce: 1011 → 0110011. Flip position 5: 0110111 → syndrome 101 → 0110011 → 1011.

Viva: Why is index 0 unused? Why are parity positions powers of two? Why does ^= 1 flip a bit?

Reference: University of New Brunswick · Hamming parity groups. Its diagram lists positions in the opposite visual order; we follow your assignment.

Read the class from the first octet

Validate all four octets, then classify using the first. The leading bits identify the historical address class. For A, B and C, the default mask splits network bits from host bits.

ClassFirst octetLeading bitsDefault mask
A0–1270/8
B128–19110/16
C192–223110/24
D224–2391110None · multicast
E240–2551111None · reserved

This is your assignment’s classful model. Modern routing uses CIDR. 0/8 and 127/8 have special meanings; matching Class A’s bit pattern does not make them ordinary usable networks. The all-ones address is limited broadcast.

Predict: 172.16.5.9 belongs to which historical class?

Write it from memory · IPv4
  1. parts = address.split("."). Require four decimal parts in 0…255.
  2. first = int(parts[0]). Apply thresholds 127, 191, 223, 239, 255.
  3. For A/B/C, print mask and 2 ** host_bits - 2.
  4. Class D/E have no ordinary classful host count or default unicast mask.
  5. Try first octets 127, 128, 191, 192, 223, 224, 239, 240; reject 10.2.3.256 and 1.2.3.

Theoretical network counts in your C++: A = 2**7 = 128; B = 2**14 = 16384; C = 2**21 = 2097152. A’s traditional usable count excludes 0 and 127, giving 126.

Viva: Why subtract two from a conventional /8, /16 or /24 host count? Network and broadcast addresses. Do not apply this rule blindly to modern /31 and /32 prefixes.

References: RFC 791 · classful address formats; RFC 1112 · Class D and E; RFC 4632 · CIDR.

Learn a cheaper route from a neighbor

A router knows its direct costs. Each round, neighbors advertise their previous distances. Try cost[i][k] + old[k][j]: the cost from router i to neighbor k, plus k’s advertised distance to destination j.

Dᵢ(j) ← min(Dᵢ(j), cost(i,k) + Dₖ(j))

Why does the previous round need its own copy?

old = [row[:] for row in distance] freezes every router’s advertisement for this round. Using a partially updated table would let some information cross multiple links within one round. A shallow outer copy alone still shares the rows.

Loop meanings: i = current router, k = direct neighbor, j = destination. On improvement, set hop[i][j] = k. Next hop is the first neighbor, not the final destination.

For the default matrix: B advertises distance 3 to D. A→B costs 1. What candidate does A calculate for D?

Write it from memory · distance vector
  1. Read N and the N×N matrix; turn input 999 into float("inf"). Set the diagonal to 0.
  2. Initialize distance with direct costs. Direct neighbors are their own next hops.
  3. Repeat: copy previous rows; set changed = False; loop i, k, j.
  4. On a strictly smaller candidate, update distance and next hop; mark changed.
  5. Stop after a round with no changes. Follow next hops to reconstruct a path.

Default matrix: A’s vector is [0,1,7,INF] initially, [0,1,3,8] after round 1, [0,1,3,4] after round 2. Round 3 confirms no changes.

Variation: remove a link in the input and rerun from initialization. This static simulation does not implement live failures, poison reverse, or RIP’s 16-hop infinity.

Viva: What is convergence? Why can a disconnected destination remain INF? Why can distance vector protocols suffer count-to-infinity after failures?

Reference: RFC 2453 §3.4 · distance vector algorithm. This lab uses arbitrary nonnegative costs and synchronous rounds rather than implementing RIP packets.

Build a connection, then take turns

Run the server first. The client sends a line, then waits; the server reads a line, then replies. TCP carries a reliable, ordered byte stream. Your application must define where a message ends.

Our Python chat ends each message with \n. reader.readline() collects a complete line even if TCP splits it across receives. sendall() handles partial sends. One recv(1024) is not guaranteed to be one message.

Run it in two terminals

Open both terminals in this repository’s root.

Terminal 1 · server

python3 python/tcp_server.py

Wait for the connection. After the client sends, type a reply.

Terminal 2 · client

python3 python/tcp_client.py

Type hello. After the server replies, send another line. Either side can send exit on its turn.

Test an empty line and a long line. If it appears stuck, check whose turn it is. If connection is refused, start the server. If the port is in use, stop the old server or change both scripts’ port default together.

Which socket does the TCP server use to send its reply?

Write it from memory · TCP

Server: socket → bind → listen → accept → read / send → close
Client: socket → connect → send / read → close

AF_INET selects IPv4. SOCK_STREAM selects TCP here. 127.0.0.1 is this machine; port 8080 identifies the lab process. Binding 0.0.0.0 would listen on all local IPv4 interfaces; use the server’s actual reachable IP as a remote client’s destination.

line == "" means the peer closed the stream. An empty chat message is "\n", so it is different. Both Python programs speak the same newline protocol; use them together.

Variation: replace a manual server reply with reply = message.upper(). Remove the server’s input() for that version.

Viva: Why bind only the server explicitly? Why does accept return a second socket? Why is TCP message framing necessary?

References: Python · Socket Programming HOWTO; Python · socket API.

Send a datagram and reverse its text

The client sends text to an address. recvfrom() gives the server both bytes and the sender’s address. It reverses the decoded text with message[::-1], then replies to that sender using sendto().

UDP preserves datagram boundaries, but delivery and order are not guaranteed. There is no listen/accept step in this lab. The client uses a five-second timeout; this visualization demonstrates that outcome without waiting five seconds.

Run it in two terminals

Terminal 1 · server

python3 python/udp_server.py

Terminal 2 · client

python3 python/udp_client.py

Send network → expect krowten. Send an empty string → expect an empty reply. Send exit → receive Server shutting down; both processes finish. Keep lab messages at most 1024 UTF-8 bytes.

Unlike TCP, a zero-byte UDP datagram is a valid message; it does not mean the peer disconnected. Without a server, your system may report an error or the receive may time out.

How does the UDP server know where to send the reversed string?

Write it from memory · UDP

Server: socket(SOCK_DGRAM) → bind → recvfrom → reverse → sendto
Client: socket(SOCK_DGRAM) → sendto → recvfrom

data, address = server.recvfrom(1025) unpacks a two-item result. message[::-1] means start at the end and step backwards. Encode the reply before sending. This reverses Python Unicode code points; complex displayed characters can contain more than one code point.

Variation: replace reversal with message.upper(), or count words with str(len(message.split())). Preserve the exit check.

Viva: Why no accept()? What happens if a datagram is lost? Who chooses the client’s source port? The OS assigns one automatically in this program.

References: Python · recvfrom and sendto; RFC 768 · UDP.
